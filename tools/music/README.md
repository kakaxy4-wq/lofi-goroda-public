# Музыка для «Лофи-городов»: пакетная генерация в ACE-Step 1.5

Набор для генерации инструментального лоуфая открытой моделью
[ACE-Step 1.5](https://github.com/ace-step/ACE-Step-1.5) (лицензия MIT) на арендованном GPU.
На рабочем ноутбуке ничего не запускаем: у него нет дискретной видеокарты.

| Файл | Что это |
|---|---|
| `prompts.json` | 60 треков: 36 «Питер» (`piter`), 24 «Казань» (`kazan`), единый стиль партии |
| `generate.py` | пакетная генерация, варианты по сидам, лог, loudnorm, фейды, mp3 |
| `make_playlist.py` | `playlist.json` в формате сайта для каждого города + копирование mp3 |

---

## 1. Какой GPU брать

Цифры ниже взяты из `docs/en/GPU_COMPATIBILITY.md` ACE-Step 1.5:

| VRAM | Что работает |
|---|---|
| ≤ 6 ГБ | только DiT 2B turbo, без LM, INT8, выгрузка на CPU |
| 8–12 ГБ | DiT 2B + LM 0.6B |
| 12–16 ГБ | DiT 2B + LM 1.7B |
| 16–24 ГБ | плюс XL DiT (на 16 ГБ с выгрузкой на CPU) |
| ≥ 24 ГБ | всё без выгрузки и квантизации |

**Рекомендация:** карта на 24 ГБ (RTX 3090, RTX 4090, A10 и т. п.). Модели `acestep-v15-turbo`
этого хватает с запасом, выгрузка не нужна. T4 (16 ГБ) тоже подойдёт, но будет медленнее.
Если VRAM меньше 12 ГБ, добавьте к запуску `--offload`.

Нужна архитектура NVIDIA не старше Volta (compute capability ≥ 7): на более старых картах
ACE-Step сам переключает LM на медленный бэкенд `pt`.

## 2. Где арендовать GPU на час

Российские облака с почасовой (или посекундной) оплатой GPU-серверов:

- **Immers.cloud** (immers.cloud). Посекундная тарификация, выбор от T4 до A100/H100,
  есть RTX 3090/4090. Образ Ubuntu с предустановленным драйвером NVIDIA.
- **Selectel** (selectel.ru → «Облачные серверы с GPU»). Почасовая оплата;
  сервер можно «заморозить», чтобы не платить за GPU между сессиями.
- **Яндекс Облако** (Compute Cloud, ВМ с GPU). Для GPU обычно нужно запросить квоту заранее,
  плюс отдельно тарифицируется исходящий трафик.

Цены меняются, смотрите калькулятор на сайте провайдера в день аренды. Сама генерация
занимает немного времени, дольше всего идут установка и первая загрузка весов (несколько ГБ).
Закладывайте час.

Что выбрать при создании ВМ: Ubuntu 22.04/24.04 с драйвером NVIDIA (CUDA), 1 GPU, 8+ vCPU,
32+ ГБ RAM, диск от 60 ГБ, доступ по SSH-ключу.

**Не забудьте удалить (или заморозить) сервер, когда скачаете результат:** почасовая оплата
идёт, пока ВМ существует.

## 3. Установка ACE-Step 1.5 на сервер

Официальный путь из README и `docs/en/INSTALL.md` (Python 3.11–3.12, менеджер `uv`):

```bash
# на сервере
nvidia-smi                                   # драйвер виден? иначе выбрать образ с драйвером
sudo apt-get update && sudo apt-get install -y git ffmpeg

curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.local/bin/env                      # или перелогиниться, чтобы uv появился в PATH

git clone https://github.com/ACE-Step/ACE-Step-1.5.git ~/ACE-Step-1.5
cd ~/ACE-Step-1.5
uv sync                                      # ставит зависимости, включая PyTorch с CUDA
uv run acestep-download                      # скачать основную модель заранее (иначе скачается при первом запуске)
```

Если Hugging Face недоступен или отвечает медленно: `uv run acestep-download --download-source modelscope`.

## 4. Загрузка набора и генерация

С рабочей машины (PowerShell или Git Bash):

```bash
scp -r tools/music user@SERVER_IP:~/music
```

На сервере:

```bash
cd ~/ACE-Step-1.5

# 1) план без генерации: что будет сделано и с какими сидами
uv run python ~/music/generate.py --dry-run --variants 2

# 2) пробный прогон на 2 треках: послушать, прежде чем гнать всю партию
uv run python ~/music/generate.py --variants 2 --limit 2

# 3) вся партия (60 треков × 2 варианта = 120 файлов)
uv run python ~/music/generate.py --variants 2
# отдельный город:  --city kazan      конкретные треки:  --ids spb-01-utro-na-karpovke
```

Если оборвалось, просто запустите ту же команду ещё раз: уже готовые `wav` пропускаются.
Сиды детерминированные (зависят от `id`, номера варианта и `--seed-base`), поэтому повторный
запуск даёт те же файлы. Если нужны третий и четвёртый варианты, запустите с `--variants 4`:
сгенерируются только `v3` и `v4`.

Что получается:

```
out/
  log.jsonl                         # строка на каждый вариант: сид, параметры, время, ошибки
  piter/spb-01-utro-na-karpovke-v1.wav
  piter/spb-01-utro-na-karpovke-v1.mp3   # loudnorm I=-16 LUFS, TP -1.5, фейды 2 с, 128k
  kazan/...
```

Полезные ключи:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `--model` | `acestep-v15-turbo` | DiT-модель; `acestep-v15-sft` качественнее, но медленнее (тогда `--steps 50 --shift 1`) |
| `--steps` / `--shift` | 8 / 3.0 | рекомендация документации для turbo |
| `--thinking` | выкл. | включить 5Hz LM (`--lm-model acestep-5Hz-lm-1.7B`); только в этом режиме работает `negative` |
| `--offload` | выкл. | `offload_to_cpu=True` для карт с малой VRAM |
| `--post-only` | | только mp3, нормализация и фейды для готовых wav |
| `--force-post` | | переделать mp3 (например, после смены `--fade`) |
| `--no-post` | | без ffmpeg-обработки |

## 5. Скачать результат

С рабочей машины:

```bash
# только mp3 и лог (wav тяжёлые, их можно не качать)
mkdir -p tools/music/out
scp "user@SERVER_IP:~/music/out/log.jsonl" tools/music/out/
scp -r "user@SERVER_IP:~/music/out/piter" "user@SERVER_IP:~/music/out/kazan" tools/music/out/
```

Если хочется скачивать только mp3, сначала упакуйте их на сервере:
`cd ~/music/out && tar czf mp3.tgz */*.mp3 log.jsonl`, потом `scp user@SERVER_IP:~/music/out/mp3.tgz .`
и распакуйте в `tools/music/out/`.

Сразу после этого удалите или заморозьте ВМ.

## 6. Положить в проект

1. Прослушайте варианты (см. чек-лист ниже) и запишите выбор в `picks.json`:
   ```json
   { "spb-01-utro-na-karpovke": 2, "spb-02-tramvaj-do-novoj-gollandii": 1, "spb-07-tuman-nad-smolenkoj": 0 }
   ```
   `0` или `null` означает «трек не брать». Трек, которого нет в `picks.json`, берётся из первого
   существующего варианта.
2. Соберите плейлист. Нужен `ffprobe` из ffmpeg. На рабочем ноутбуке ffmpeg сейчас нет:
   поставьте его сами (например, `winget install Gyan.FFmpeg`) или запустите
   `make_playlist.py` на сервере и скачайте готовую папку `out/<city>/release/`.
   ```bash
   # из корня репозитория: оба города сразу, уже лежащие на сайте треки сохраняются (--merge)
   python tools/music/make_playlist.py --dest "site/cities/{city}/music" --picks picks.json --merge
   ``````
   Скрипт копирует выбранный mp3 как `<id>.mp3`, меряет длительность через ffprobe
   (с точностью до 0,1 с) и пишет `playlist.json`:
   `[{"src": "cities/piter/music/spb-01-utro-na-karpovke.mp3", "title": "Утро на Карповке", "dur": 183.4}, ...]`.
   Префикс `src` — `--src-prefix`, по умолчанию `cities/{city}/music/` (как на сайте).
3. Обновите сайт в браузере и проверьте, что треки играют и переключаются.
   Коммит и деплой делайте сами, когда всё устроит.

## 7. Чек-лист прослушивания

Каждый выбранный вариант прослушайте хотя бы в начале, в середине и в последние 20 секунд.

- [ ] **Нет вокала:** ни слов, ни «хора», ни мычания, ни голосовых сэмплов. Если что-то есть,
      берите другой вариант или догенерируйте (`--variants 3`).
- [ ] **Мягкие концы:** трек не обрывается на полутакте, фейд-аут слышен, в начале нет щелчка.
- [ ] **Ровная громкость:** при переходе между треками не приходится трогать регулятор.
      Все mp3 нормализованы к −16 LUFS, но выбивающийся трек лучше заменить.
- [ ] **Стиль партии:** темп спокойный, ударные мягкие, нет EDM-дропов и трэп-хэтов.
- [ ] **Казань:** лёгкий пентатонический оттенок без «восточной» стилизации
      (нет увеличенной секунды, уда, дарбуки).
- [ ] **Нет артефактов:** металлического звона, «жевания», провалов, резкого клиппинга.
- [ ] **Длительность** около 150–210 с (см. `dur` в плейлисте).

## 8. Лицензия и маркировка

- ACE-Step 1.5 распространяется по лицензии **MIT**. Перед публикацией на всякий случай
  перечитайте `LICENSE` и карточку модели на Hugging Face (`ACE-Step/Ace-Step1.5`): условия
  на веса и на код могут отличаться, и их стоит сверить в день использования.
- Честная пометка на сайте и в описании радио, например:
  «Музыка сгенерирована ИИ (ACE-Step 1.5) по нашим текстовым описаниям и отобрана вручную».
- Не добавляйте в `tags` имена реальных артистов и названия чужих треков.
- Лог `out/log.jsonl` хранит сид и параметры каждого трека. Сохраните его: так всегда можно
  показать происхождение трека и воспроизвести его.

## 9. Что в `generate.py` подтверждено документацией ACE-Step, а что допущение

Подтверждено (`docs/en/INFERENCE.md`, `docs/en/INSTALL.md`, `docs/en/GPU_COMPATIBILITY.md`):
`AceStepHandler().initialize_service(project_root, config_path, device)`,
`LLMHandler().initialize(checkpoint_dir, lm_model_path, backend, device)`,
`generate_music(dit_handler, llm_handler, params, config, save_dir=...)`,
поля `GenerationParams`: `caption`, `lyrics`, `instrumental`, `bpm`, `keyscale`, `timesignature`,
`duration`, `seed`, `inference_steps`, `shift`, `thinking`, `lm_negative_prompt`, `use_cot_*`;
поля `GenerationConfig`: `batch_size`, `use_random_seed`, `seeds`, `audio_format` (в том числе `"wav"`);
результат: `result.success`, `result.error`, `result.audios[i]["path"]`, `["params"]["seed"]`.
Для turbo рекомендованы `steps=8` и `shift=3.0`.

Ограничения и допущения:
- **Отдельного negative prompt у DiT нет.** Есть только `lm_negative_prompt` для языковой модели,
  и он работает только с `--thinking`. Поле `negative` в `prompts.json` передаётся туда.
  Без LM отсутствие вокала обеспечивается через `instrumental=True` + `lyrics="[Instrumental]"`,
  как советует документация.
- Имя выходного файла в документации не описано. В коде оно выглядит как `<uuid>.<ext>`
  внутри `save_dir`, поэтому скрипт пишет во временную папку и переносит файл по `audio["path"]`.
- Предзагрузка моделей через `acestep.model_downloader` (`ensure_main_model` и др.) в документации
  не описана, её вызывает их `cli.py`. Поэтому вызов обёрнут в `try`, а при ошибке остаётся
  автозагрузка при первом запуске.
- Официальный `cli.py` работает только через мастер или TOML-конфиг и не принимает параметры
  генерации флагами. Поэтому для пакетного режима взят Python API.
- Точные цены аренды и время генерации в этом README не указаны: их нужно смотреть
  у провайдера и в `log.jsonl` (поле `elapsed_s`).
